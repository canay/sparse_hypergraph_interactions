This directory holds the experiment bundles behind the manuscript *A Transparent
Ranker–Policy Benchmark for Pair and Triple Interaction-Support Selection*. It is
a separate object from `../replication_package/`, which holds the earlier
implementation and is the package described by an earlier submission; nothing in
that directory was changed when this one was added.

## What the numbers here do and do not establish

The predeclared confirmatory verdict of the original benchmark is **unavailable**,
because one scenario-seed cell failed the exact-cardinality requirement and the
protocol prohibits imputation, cell deletion, or a fallback interval. Every
comparison in these records is therefore descriptive. They do not establish that
one ranker is better than another, and they do not establish that the adaptive
support policy helps. The records are published so that the descriptive claims in
the manuscript can be checked against the artifacts that produced them.

## Verifying the bundle

`SOURCE_MAP.json` carries a SHA-256 for every path of the canonical bundle. Two
paths are stored differently **here** and only here:

```text
data/v5/full-synthetic-primary/fit_calls.csv   ->  ...csv.gz
data/v5/full-real-descriptive/fit_calls.csv    ->  ...csv.gz
```

GitHub rejects a single file above 100 MB without Git LFS and the first of those
is 110.1 MB. Both are stored gzipped for consistency with the 400 record files in
this bundle that are already gzipped. `REPOSITORY_PACKAGING.json` records each
one's original size and digest beside the stored ones, so the original bytes are
recoverable and checkable:

```bash
gzip -d data/v5/full-synthetic-primary/fit_calls.csv.gz
gzip -d data/v5/full-real-descriptive/fit_calls.csv.gz
# then every SOURCE_MAP.json digest applies as written
```

No other file differs from the canonical bundle.

## What is not here

Raw public benchmark data are not redistributed. Dry Bean is retrieved from UCI
under DOI 10.24432/C50S4B and verified against the recorded archive and ARFF
hashes before use; synthetic data are generated by the code in `code/`.
